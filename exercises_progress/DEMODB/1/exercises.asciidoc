= Exercises
:toc: left
:toclevels: 3

The exercises on the installed `demo` database, the PostgreSQL demonstration database (https://postgrespro.com/community/demodb[Airlines]), in its `bookings` schema: a section for each table and view, with a section for each level, and, at the end, a section for the schema as a whole.
Each exercise poses a problem; its answer, and what the installed data gives back, are in the `.sql` file.
The data is the `3m` edition, three months of flights from 2025-10-01, and the database's today, `bookings.now()`, is 2025-12-01; the views read the names in the language `bookings.lang()` returns, `en`.

Run a file as a whole:

[source,sh]
----
docker exec -i postgresql-demodb psql -U postgres -d demo < src/test/sql-exercises/<section>/<NN>_<level>.sql
----

[[DEMODB_AIRPLANES_DATA_A_02]]
==== DEMODB_AIRPLANES_DATA_A_02: the airplanes by the flights they fly

Count the flights each airplane flies: a flight's airplane is the one of the route's row valid at the flight's scheduled departure.
Show the code, the English name and the count, the most first; airplanes with the same count are ordered by `airplane_code`.
Two joins, the second on a range containment (`@>`), and a group.

.`airplanes_data/03_advanced.sql`, DEMODB_AIRPLANES_DATA_A_02
[%collapsible]
====
[source,sql]
----
SELECT a.airplane_code, a.model ->> 'en' AS model, COUNT(f.flight_id) AS flights
FROM airplanes_data a
         JOIN routes r ON r.airplane_code = a.airplane_code
         JOIN flights f ON f.route_no = r.route_no AND r.validity @> f.scheduled_departure
GROUP BY a.airplane_code, a.model
ORDER BY flights DESC, a.airplane_code
----

[[DEMODB_AIRPLANES_I_02]]
==== DEMODB_AIRPLANES_I_02: whether the view agrees with the table

Join the view to `airplanes_data` and find the rows whose `model` differs from the table's name in the session's language, `model ->> lang()`.
Show the code and both names; there should be none.
`IS DISTINCT FROM` treats a `NULL` on either side as a difference.

.`airplanes/02_intermediate.sql`, DEMODB_AIRPLANES_I_02
[%collapsible]
====
[source,sql]
----

FROM airplanes v
         JOIN airplanes_data d ON d.airplane_code = v.airplane_code
WHERE v.model IS DISTINCT FROM d.model ->> lang()
ORDER BY v.airplane_code
----

[[DEMODB_AIRPLANES_A_02]]
==== DEMODB_AIRPLANES_A_02: the airplanes ranked by speed, ties sharing a rank

Rank the airplanes by `speed`, the fastest first, both ways: airplanes of the same speed share a rank, and `RANK` then skips the ranks they took up, while `DENSE_RANK` does not.
Airplanes of the same speed are listed by `airplane_code`.
Two ranking windows over the same order.

.`airplanes/03_advanced.sql`, DEMODB_AIRPLANES_A_02
[%collapsible]
====
[source,sql]
----
SELECT airplane_code,
       model,
       speed,
       RANK() OVER (ORDER BY speed DESC)       AS rank,
       DENSE_RANK() OVER (ORDER BY speed DESC) AS dense_rank
FROM airplanes
ORDER BY speed DESC, airplane_code
----

[[DEMODB_AIRPORTS_DATA_A_01]]
==== DEMODB_AIRPORTS_DATA_A_01: the cities with more than one airport

Group the airports by city and country, in English, and keep the cities with more than one.
Show the city, the country, the codes joined into one string in order, and the count: the most airports first, then by city; the first ten.
A group on two `jsonb` fields, `HAVING`, and `string_agg` with its own `ORDER BY`.

.`airports_data/03_advanced.sql`, DEMODB_AIRPORTS_DATA_A_01
[%collapsible]
====
[source,sql]
----
SELECT city ->> 'en'                                       AS city,
       country ->> 'en'                                    AS country,
       STRING_AGG(airport_code, ', ' ORDER BY airport_code) AS airports,
       COUNT(*)                                            AS count
FROM airports_data
GROUP BY city ->> 'en', country ->> 'en'
HAVING COUNT(*) > 1
ORDER BY count DESC, city
LIMIT 10
----

SELECT DISTINCT r1.route_no, r2.route_no AS return_route_no, r1.departure_airport, r1.arrival_airport
FROM routes r1
         JOIN routes r2 ON r2.departure_airport = r1.arrival_airport
    AND r2.arrival_airport = r1.departure_airport
    AND r2.validity && r1.validity
WHERE r1.departure_airport < r1.arrival_airport
ORDER BY r1.route_no, r2.route_no
LIMIT 10
----

[[DEMODB_ROUTES_A_03]]
==== DEMODB_ROUTES_A_03: the airplane changes of each route from one period to the next

A route number has a row per period of validity, and its airplane may change from one period to the next.
For each period whose airplane differs from the previous period's, show the route, the start of the period, the previous airplane and the new one.
`LAG`, partitioned by `route_no` and ordered by `validity`, reads the previous period; ranges sort by their lower bounds first.
The first period of a route has no previous one: `LAG` gives `NULL`, and `<>` with a `NULL` is never true, so the row drops out.

.`routes/03_advanced.sql`, DEMODB_ROUTES_A_03
[%collapsible]
====
[source,sql]
----
SELECT route_no, valid_from, previous_airplane, airplane_code
FROM (SELECT route_no,
             LOWER(validity)                                                   AS valid_from,
             airplane_code,
             LAG(airplane_code) OVER (PARTITION BY route_no ORDER BY validity) AS previous_airplane
      FROM routes) r
WHERE previous_airplane <> airplane_code
ORDER BY route_no, valid_from
----

==== DEMODB_TIMETABLE_A_02: the connections at Sheremetyevo on the first day

For each flight scheduled to arrive at `SVO` on 2025-10-01, find the flights departing from `SVO` between one and four hours after its scheduled arrival.

[source,sql]

WHERE a.arrival_airport = 'SVO'
  AND a.scheduled_arrival >= '2025-10-01'
  AND a.scheduled_arrival < '2025-10-02'
ORDER BY a.flight_id, d.flight_id
LIMIT 10
----
