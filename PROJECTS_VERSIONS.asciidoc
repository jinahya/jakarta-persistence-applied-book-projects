= Projects versions

The versions every submodule under `projects/` is to be aligned on.
`_alignment.py` reads the tables below, resolves what each submodule actually uses, once per Jakarta EE generation and
persistence provider it builds for, and records the result in link:../README.asciidoc[].

An artifact under <<every-generation>> has the same version in every generation; the test stack is not tied to one.
An artifact under <<libraries>> has the same version in every generation and every submodule that uses it.
An artifact under a `Jakarta EE <N>` section has that version for that generation only.
An artifact under <<spring>> is at its latest release, and belongs to the one generation its row names.
A new generation gets a section of its own, and a submodule builds for it with a `jakarta-ee-<N>` or
`jakarta-ee-<N>-<provider>` profile.
`jakarta.jakartaee-bom` is read from a submodule's pom, since it is imported and never shows up as a dependency; every
other artifact is read from `dependency:list`.

== Decisions

* JUnit 6, the line Spring Boot 4 already brings, at its latest release. (2026-10-23)
* Two providers, Hibernate ORM and EclipseLink, where they apply: a plain Jakarta Persistence mapping module runs on
  both. `mysql-sakila-jakarta-data` stays on Hibernate ORM, since its repositories are generated by Hibernate's
  processor, and `mysql-sakila-spring-data` does too, since Spring Boot wires Hibernate. (2026-10-23)
* Spring Framework and Spring Boot at their latest releases, as long as they conform to the generation: a Spring Boot
  line counts for a generation only if the Jakarta Persistence and Hibernate ORM it manages are that generation's.
  Spring Boot 4.1.2 manages Spring Framework 7.0.10, Jakarta Persistence 3.2.0 and Hibernate ORM 7.4.13.Final, so it
  is Jakarta EE 11's. (2026-10-23)
* The other libraries the submodules use, from Podam to the JDBC drivers, are managed here too, at their latest
  releases, under <<libraries>>; an implementation of a Jakarta specification (Hibernate Validator, Expressly) goes
  with its generation instead. A milestone counts only where every submodule is already on it (AssertJ 4.0.0-M1).
  (2026-10-23)

[[spring]]
== Spring

Spring Framework and Spring Boot are not picked per generation: they stay at their latest releases.
The latest Spring Boot line belongs to the one Jakarta EE generation whose Jakarta Persistence and Hibernate ORM it
manages, and a submodule built on Spring Boot is on that generation.
When a new Spring Boot line moves to a newer generation, its row moves with it.

|===

Spring Boot 4.1.2 manages Spring Framework 7.0.10, Jakarta Persistence 3.2.0 and Hibernate ORM 7.4.13.Final.
The versions the latest Spring Boot manages are listed in
https://docs.spring.io/spring-boot/appendix/dependency-versions/coordinates.html[Managed Dependency Coordinates];
check its Jakarta Persistence and Hibernate ORM rows there to see which generation it belongs to.
